# Атрибуция контрибьюторов

## Основной принцип

Авторство в Git должно отражать вклад реальных людей. Поля `Author`, `Committer` и trailers авторства используются для людей, которые создали, переработали или содержательно проверили изменение.

AI-сервис, модель, агент или редактор кода не является автором или соавтором материала. Не указывайте AI-инструменты в:

- `Author`;
- `Committer`;
- `Co-Authored-By`;
- `Signed-off-by`;
- других trailers, которые GitHub интерпретирует как авторство или участие.

Использование AI-инструмента можно указать в описании PR как часть процесса подготовки материала. Это не должно заменять или размывать атрибуцию реального автора.

## Настройка Git

Перед созданием коммитов проверьте имя и email:

```bash
git config user.name
git config user.email
```

Используйте имя реального автора и email, добавленный и подтверждённый в его аккаунте GitHub. Для приватности можно использовать GitHub `noreply`-адрес конкретного пользователя.

Проверьте коммиты ветки перед push:

```bash
git log --format='%h %an <%ae>%n%B%n---' origin/main..HEAD
```

Убедитесь, что:

- имя и email принадлежат реальному участнику;
- email связан с нужным аккаунтом GitHub;
- в сообщениях нет AI-инструментов в trailers авторства;
- человеческие соавторы указаны корректно и с их согласия.

## Работа с внешним PR

Не заменяйте автора внешнего вклада собственным аккаунтом, техническим пользователем или AI-инструментом.

Если сопровождающий вносит дополнительные изменения в ветку участника:

1. сохраняйте исходные коммиты участника;
2. оформляйте редакторские исправления отдельными коммитами;
3. не приписывайте AI-инструменту соавторство;
4. при squash merge сохраните упоминание реального автора в commit metadata или в человеческом `Co-Authored-By`, если GitHub иначе потеряет атрибуцию.

## Исправление до merge

Если ошибочная атрибуция находится в незамерженной ветке автора, исправьте её до merge:

```bash
git commit --amend --author='Имя автора <email@example.com>'
```

Для нескольких коммитов используйте interactive rebase, удалите AI-trailers и проверьте author email. После переписывания собственной ветки потребуется безопасный force-push:

```bash
git push --force-with-lease
```

Не переписывайте чужую ветку без согласования с её владельцем.

## Исправление после merge

Не переписывайте `main` только ради косметической коррекции списка Contributors: это изменит SHA всех последующих коммитов и создаст лишний риск.

Если GitHub не связал уже замерженный коммит с реальным автором:

1. определите email автора коммита:

   ```bash
   git show -s --format='%ae' <commit-sha>
   ```

2. добавьте и подтвердите этот email в GitHub → Settings → Emails;
3. оставьте пояснение в исходном PR, если AI-инструмент ошибочно указан соавтором;
4. дождитесь пересчёта статистики GitHub.

Старый AI-trailer останется в истории без её переписывания, но реальный автор будет корректно связан со своим аккаунтом.

## Автоматическая проверка

Репозиторий проверяет в новых PR поля `Author` и `Committer`, а также trailers участия в сообщениях коммитов, включая `Co-Authored-By`, `Signed-off-by` и другие поля с окончанием `-by`. Проверка отклоняет очевидные AI-идентичности: Claude, ChatGPT, Codex, GitHub Copilot, Gemini и служебные адреса доменов Anthropic и OpenAI.

Автоматическая проверка не заменяет ручное ревью: необычная AI-идентичность или неверный email реального автора может не попасть под шаблон проверки.
