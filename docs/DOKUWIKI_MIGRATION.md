# Миграция DokuWiki-синтаксиса в Markdown/MDX

Этот файл сохраняет практические правила старой энциклопедии и определяет, как переносить их в текущий Astro/Starlight-стек.

## Источники

Исторический синтаксис проекта основан на старой странице `wiki:syntax` и использовавшихся в статьях DokuWiki-плагинах.

Для проверки используйте актуальную ветку `main` репозитория `Antiokh/rslive.ru`:

- `docs/DOKUWIKI_COMPONENT_AUDIT.md`;
- `docs/ASTRO_MIGRATION_AGENT.md`;
- `astro/astro.config.mjs`;
- `astro/src/components/`;
- исходные страницы в `www/doku-secure/data/pages`, когда они доступны.

Аудит может перечислять предполагаемые названия будущих компонентов. Они не считаются доступными, пока не существуют в текущем коде и не включены в автоимпорт. При расхождении аудита, этого документа и реализации приоритет имеет `astro/astro.config.mjs` и исходник компонента.

Этот документ описывает целевой синтаксис. Старый DokuWiki-синтаксис нельзя оставлять в рабочих MDX-страницах, кроме архивного примера внутри fenced code block.

## Основной принцип

Не удаляйте смысл или функцию только потому, что старая конструкция не поддерживается MDX.

Каждая конструкция должна стать одним из вариантов:

1. обычным Markdown;
2. существующим автоимпортируемым MDX-компонентом;
3. структурированными данными;
4. безопасным статическим текстом;
5. явно отмеченной задачей миграции, если эквивалента ещё нет.

Запрещено исполнять старые HTML/PHP-блоки, выдумывать отсутствующие компоненты или переносить приватную служебную логику в публичный контент.

## Быстрая таблица преобразований

| DokuWiki | Astro/MDX | Примечание |
| --- | --- | --- |
| `====== Заголовок ======` | frontmatter `title` или `#` | В статье обычно не дублируйте H1 после `title` |
| `===== Раздел =====` | `## Раздел` | Уровни пересчитайте по смыслу |
| `==== Подраздел ====` | `### Подраздел` | Не переносите механически количество `=` |
| `**жирный**` | `**жирный**` | Совпадает |
| `//курсив//` | `*курсив*` | Не используйте `//` |
| `__подчёркивание__` | обычный текст или `<u>` | Подчёркивание используйте редко |
| `''код''` | `` `код` `` | Inline code |
| `<sub>`, `<sup>`, `<del>` | MDX HTML / `~~текст~~` | Используйте намеренно |
| `[[page:name|Текст]]` | `[Текст](/page/name/)` | Проверяйте существование маршрута |
| `[[#раздел|Текст]]` | `[Текст](#проверенный-id)` | ID проверяйте в Astro |
| `[[https://...|Текст]]` | `[Текст](https://...)` | Не используйте angle autolink |
| `[[wp>Article]]` и другие interwiki | обычная внешняя ссылка | Разверните сокращение в URL |
| `((сноска))` | `[^1]` + определение | Только числовые сноски |
| два пробела + `*` | `-` | Маркированный список |
| два пробела + `-` | `1.` | Нумерованный список |
| DokuWiki-таблица `^` / `|` | Markdown table / таблица-компонент | Объединённые ячейки требуют переработки |
| `<code lang>` | fenced code block | Укажите язык после тройных backticks |
| `<file>` | fenced code block + ссылка на файл | Автоскачивание старого блока не переносится автоматически |
| `%%...%%` / `<nowiki>` | inline code / fenced code | Выберите по объёму |
| `{{image.png?200|alt}}` | `![alt](путь)` | Проверьте существование asset |
| `[[url|{{image}}]]` | `[![alt](image)](url)` | Добавьте осмысленный alt |
| `{{section>page#section}}` | `ContentInclude` / статическое включение | Проверяйте исходник и section |
| `{{page>page}}` | `ContentInclude` / статическое включение | Не создавайте циклы |
| `++++ Заголовок|...++++` | `Spoiler` | Для одного скрытого блока |
| `<panel>...</panel>` | `Spoiler`, `AccordionItem`, `Aside` или обычный раздел | Выберите по смыслу |
| `<accordion>` / `<accordion-item>` | `Accordion` / `AccordionItem` | Сохраняйте заголовки элементов |
| `<callout>` / `<alert>` | `Aside` | Нормализуйте тип |
| `<uplatnica ... />` | `UplatnicaGenerator` | Сохраняйте все платёжные поля |
| `<countdown=...>` | `Countdown` | Укажите фиксированную или ежегодную дату |
| `<mermaid>` | `MermaidGraph` | Передайте код через prop |
| `{{youtube>...}}` | `YouTube` | ID или поддерживаемый URL |
| `{{simplemap>...}}` | `MapEmbed` | Сохраняйте текстовый адрес |
| `{{url>...}}` / `<url>` | `MapEmbed`, `YouTube` или `EmbedFrame` | Выберите по типу ресурса |
| `<datatable>` / `<datatables>` | `SmartTable`, `StructTable`, `SupabaseTable`, `SanityTable` | Не копируйте управляемые данные вручную |
| `<WRAP>`, `<grid>`, `<col>` | обычная структура, `CardGrid`, таблица или отдельный компонент | Не переносите layout-теги как есть |
| `<label>` / `<badge>` | `Badge` или обычный текст | Проверьте семантику |
| `<tooltip>` / `<autott>` | текст, сноска или `title` | Не скрывайте существенную информацию в tooltip |
| `{{flag>...}}` | Unicode-флаг, название страны или проверенное изображение | Компонент `Flag` сейчас не автоимпортируется |
| `{{avatar>...}}` | обычное изображение или metadata автора | Проверьте asset, alt и лицензию |
| `{{changes>...}}` | удалить, дать ссылку на историю GitHub или сделать статический архив | Не переносите служебный токен |
| `{{blog>...}}` | ссылка на `/blog/` или возможности `starlight-blog` | Не выдумывайте компонент списка |
| `{{simplenavi>...}}`, `<nspages>`, `<catlist>` | Starlight sidebar или вручную проверенный список ссылок | Проверяйте реальные маршруты |
| `<barcode>` | обычная ссылка/изображение или задача на новый компонент | `QrCode` не реализован автоматически |
| `<achart>` | существующий специализированный график либо новый компонент | `DiasporaChart` подходит только для встроенного набора данных |
| `<do>` / `{{dolist>...}}` | удалить из статьи / GitHub issue | Это рабочий процесс, не публичный контент |
| `<ifauth>` | удалить или переписать публично | Не переносите приватный блок без проверки |
| `{{tag>...}}` | frontmatter `keywords` / будущая taxonomy | Не выводите старый токен в тексте |
| `{{htmlmetatags>...}}` | frontmatter | Перенесите title, description и изображения |
| `~~NOTOC~~` | frontmatter / структура страницы | Проверяйте поддержку текущей темы |
| `~~NOCACHE~~` | удалить | Статическая сборка не использует DokuWiki cache macro |
| `<html>`, `<php>` | не исполнять | Только fenced code, если это пример |
| `{{rss>...}}` | обычная ссылка или специальный компонент после реализации | Не оставляйте старый токен |

## Заголовки

Старый DokuWiki использовал число знаков `=` для уровня заголовка. В Astro первый заголовок страницы задаётся через frontmatter:

```mdx
---
title: "Белый картон"
description: "Как зарегистрировать место пребывания иностранца в Сербии."
---

## Кто должен оформить регистрацию

### Срок подачи
```

Правила:

- Не добавляйте `# Белый картон`, если `title` уже создаёт H1.
- Не перескакивайте с `##` на `####` без причины.
- Не используйте заголовок только ради жирного текста.
- После изменения заголовка проверьте входящие ссылки на якорь.

## Форматирование

Старое:

```text
**жирный**
//курсив//
__подчёркнутый__
''моноширинный''
```

Новое:

```mdx
**жирный**
*курсив*
`моноширинный`
```

Подчёркивание обычно заменяйте смысловым выделением или обычным текстом. Не злоупотребляйте вложенными комбинациями оформления.

Принудительные DokuWiki-переносы `\\` заменяйте абзацем, списком или Markdown hard break только когда перенос действительно нужен.

## Ссылки

### Внутренние

Старое:

```text
[[arrival:boravak|РВП и ВНЖ]]
```

Новое:

```mdx
[РВП и ВНЖ](/arrival/boravak/)
```

Порядок проверки:

1. Найдите `src/content/docs/arrival/boravak/index.mdx`.
2. Проверьте маршрут в `CONTENT_INDEX.yml`.
3. Используйте абсолютный путь с завершающим `/`.

### Ссылки на разделы

Старое:

```text
[[#внутренние|этот раздел]]
```

Новое:

```mdx
[этот раздел](#проверенный-heading-id)
```

Не транслитерируйте ID вручную по старым правилам DokuWiki. Проверьте фактический Astro ID.

### Interwiki

Старые сокращения `wpru>`, `wpsr>`, `google>`, `telegram>`, `whatsapp>`, `tel>` и аналогичные разворачивайте в обычные URL:

```mdx
[Русская Википедия](https://ru.wikipedia.org/wiki/...)
[Telegram](https://t.me/username)
[WhatsApp](https://wa.me/381...)
[Позвонить](tel:+381...)
```

Проверьте корректность и безопасность URL. Не переносите неизвестный interwiki alias без расшифровки.

## Сноски

Старое:

```text
Утверждение((Комментарий или источник)).
```

Новое:

```mdx
Утверждение.[^1]

[^1]: [Официальный источник](https://example.com).
```

Правила:

- Используйте только числовые метки.
- Для фактического утверждения указывайте источник, а не только пояснение.
- Не помещайте важное условие исключительно в сноску.

## Списки

Старые DokuWiki-списки определяли тип символом после отступа. В Markdown используйте стандартный синтаксис:

```mdx
- первый пункт;
- второй пункт:
  - вложенный пункт.

1. Первый шаг.
2. Второй шаг.
```

Для процедур с последовательностью используйте `Steps`:

```mdx
<Steps>
1. Подготовьте документы.
2. Подайте заявление.
3. Получите подтверждение.
</Steps>
```

## Таблицы

Простую таблицу переносите в Markdown:

```mdx
| Документ | Где получить |
| --- | --- |
| Паспорт | Орган выдачи |
| Подтверждение адреса | МВД или eUprava |
```

Старые объединённые строки и колонки (`||`, `:::`, смешанные `^`) не поддерживаются обычным Markdown. Перестройте данные так, чтобы каждая строка была самостоятельной.

Выбор компонента:

- небольшая статичная таблица — Markdown;
- большая статичная таблица с фильтром — `SmartTable`;
- известная управляемая схема — `StructTable`;
- Supabase — `SupabaseTable`;
- Sanity — `SanityTable`.

Не оставляйте `<datatable>` и не превращайте динамическую таблицу в устаревающую ручную копию.

## Код, file и nowiki

Старое:

```text
<code bash>
echo "hello"
</code>
```

Новое:

````mdx
```bash
echo "hello"
```
````

`<file>` не создаёт автоматически скачиваемый файл в текущем стеке. Если читателю нужен файл:

1. добавьте его в подходящее публичное место основного репозитория;
2. покажите содержимое fenced code block, если это полезно;
3. дайте обычную ссылку на скачивание.

`%%...%%` и `<nowiki>` заменяйте inline code или fenced code block.

## Изображения и файлы

Старое:

```text
{{wiki:image.png?200|Описание}}
```

Новое:

```mdx
![Описание](/path/image.png)
```

Проверьте:

- реальное существование файла;
- публичный URL;
- осмысленный alt;
- лицензию;
- необходимость размера и адаптивности.

Старое выравнивание пробелами внутри `{{ ... }}` не переносится. Используйте текущие стили или компонент только при необходимости.

## Callout и alert

Старое:

```text
<callout type="primary" title="Важно">
Текст.
</callout>
```

Новое:

```mdx
<Aside type="note" title="Важно">
  Текст.
</Aside>
```

Нормализация типов:

| Старый смысл | Новый тип |
| --- | --- |
| нейтральное пояснение, `primary`, `info` | `note` |
| практический совет, `success` | `tip` |
| ограничение, `warning`, вопрос для проверки | `caution` |
| непосредственный серьёзный риск, `danger` | `danger` |

Выбирайте по смыслу, а не по цвету старого блока.

## Спойлеры, panel и accordion

Один скрытый блок:

```mdx
<Spoiler title="Показать пример">
  Дополнительный пример.
</Spoiler>
```

Группа:

```mdx
<Accordion title="Частые вопросы">
  <AccordionItem title="Первый вопрос">
    Ответ.
  </AccordionItem>
  <AccordionItem title="Второй вопрос">
    Ответ.
  </AccordionItem>
</Accordion>
```

Ключевую информацию не скрывайте. Старый `<panel>` может быть не спойлером, а обычным разделом или `Aside`; определяйте по содержанию.

## Uplatnica

Старое:

```text
<uplatnica
  subject="Назначение платежа"
  recipient="Получатель"
  sum="0.00"
  account="000-0000000000000-00"
  target="индивидуальный номер"
  model="00"
/>
```

Новое:

```mdx
<UplatnicaGenerator
  payer="Имя Фамилия, адрес"
  subject="Назначение платежа из официальной инструкции"
  recipient="Получатель из официальной инструкции"
  code="000"
  sum="0.00"
  account="000-0000000000000-00"
  target="индивидуальный номер"
  model="00"
/>
```

Пример показывает синтаксис, а не действующие реквизиты.

Обязательно:

- сохраните все поля;
- проверьте сумму и реквизиты по актуальному официальному источнику;
- не подставляйте общий `target`, если он формируется индивидуально;
- не храните в исходном MDX реальные персональные данные плательщика;
- учтите, что текущая реализация передаёт QR payload внешнему сервису `api.qrserver.com` через URL запроса;
- не заменяйте компонент картинкой;
- проверьте результат в сборке основного репозитория.

## Включения section и page

Старое:

```text
{{section>move:visa#безвизовое_пребывание}}
{{page>move:visa}}
```

Новое:

```mdx
<ContentInclude page="move:visa" section="безвизовое-пребывание" noHeader />
<ContentInclude page="move:visa" />
```

Правила:

- проверьте исходный файл и существующий заголовок;
- не допускайте циклов;
- проверьте сноски;
- учитывайте, что фрагмент отдельно обрабатывается Markdown-процессором: MDX/JSX-компоненты внутри включения требуют проверки сборкой;
- при нестабильном или критичном фрагменте проверьте собранный HTML;
- если включение делает статью непонятной без контекста, перепишите структуру.

## Карты, iframe и видео

Выбирайте компонент по содержанию:

```mdx
<MapEmbed src="https://..." title="Карта" />
<YouTube id="VIDEO_ID" title="Название видео" />
<EmbedFrame src="https://..." title="Интерактивный материал" />
```

Не переносите `{{url>...}}`, `<url>` или `{{youtube>...}}` буквально.

## Countdown

Старое:

```text
<countdown=D:2027-03-14|до события ##DATE##>
```

Новое:

```mdx
<Countdown date="2027-03-14" label="до события ##DATE##" />
```

Ежегодный срок:

```mdx
<Countdown date="04-30" annual label="до ежегодного срока ##DATE##" />
```

Рядом укажите точную дату и источник. Счётчик — интерфейсное дополнение, а не единственное описание срока.

## Mermaid

Старое:

```text
<mermaid>
flowchart TD
A --> B
</mermaid>
```

Новое:

```mdx
<MermaidGraph code={`flowchart TD
  A --> B`} />
```

Проверьте синтаксис и не используйте HTML-вставки внутри Mermaid.

## WRAP, grid и col

Не переносите layout-разметку буквально.

Определите смысл:

- карточки равноправных вариантов — `CardGrid`;
- данные — таблица;
- последовательность — `Steps`;
- обычный текст — разделы Markdown;
- уникальный сложный layout — новый компонент в `Antiokh/rslive.ru` после обоснования.

Не используйте сырой `<div style="...">` для воспроизведения старой сетки без необходимости.

## Tooltip и autott

Старые подсказки часто скрывали пояснение:

```text
<tooltip title="Пояснение">термин</tooltip>
<autott>...</autott>
```

Целевой выбор:

- короткое определение — напишите рядом;
- источник или дополнительное пояснение — сноска;
- необязательная деталь — `Spoiler`;
- нативный `title` допустим только для некритичного интерфейсного пояснения.

Не скрывайте юридическое условие только во всплывающей подсказке.

## Конструкции без прямого компонента

### flag

`{{flag>...}}` не заменяйте несуществующим `<Flag>`. Используйте Unicode-флаг вместе с названием страны либо проверенное изображение с alt-текстом, если флаг действительно нужен.

### avatar

`{{avatar>...}}` переносите в обычное изображение или author metadata. Проверьте, что файл существует, его можно публиковать и изображение не используется вместо имени автора.

### changes

`{{changes>...}}` показывал историю изменений DokuWiki. В статье его обычно удаляют. Если история важна, дайте ссылку на GitHub history конкретного файла или подготовьте статический архив.

### blog, simplenavi, nspages и catlist

Не переносите служебные генераторы списков буквально. Используйте `/blog/`, Starlight sidebar или вручную составленный список существующих страниц. Проверяйте каждый маршрут по дереву и `CONTENT_INDEX.yml`.

### barcode

Не используйте предполагаемый `QrCode`, пока его нет в коде и автоимпорте. Сохраните ссылку или проверенное изображение либо создайте отдельную задачу на компонент в `Antiokh/rslive.ru`.

### achart

`DiasporaChart` содержит конкретный встроенный набор статистики и не является общим графиком. Используйте его только для этого набора с источником и датой проверки; для других данных реализуйте отдельный компонент.

## Служебные плагины

### do и dolist

`<do>` и `{{dolist>...}}` — редакционные задачи. В публичной статье их быть не должно.

Перенесите задачу в:

- GitHub issue;
- описание PR;
- проектный tracker.

### ifauth

`<ifauth>` обозначал приватный или авторизованный блок. Перед переносом определите:

- должен ли текст быть публичным;
- содержит ли он внутренние данные;
- является ли он редакционной инструкцией.

Не публикуйте приватное содержимое автоматически.

### html и php

Никогда не исполняйте старый код. Если это документационный пример, поместите его в fenced code block. Если это функциональность сайта, реализуйте безопасный Astro-компонент или серверную функцию в основном репозитории.

### NOTOC и NOCACHE

- `~~NOCACHE~~` удалите.
- `~~NOTOC~~` заменяйте только после проверки текущей поддержки frontmatter/темы. Не вставляйте старый токен.

- [ ] нет `[[...]]`;
