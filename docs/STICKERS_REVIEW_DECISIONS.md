# Решения по семантике стикеров

Этот файл фиксирует принятые после review решения для переноса в канонический классификатор движка. Исходный `STICKERS_REVIEW.md` остаётся журналом сверки и привязкой к inline-комментариям PR.

Важно: будущий `alt` должен описывать только то, что буквально видно на изображении. Референсы, авторские шутки и редакционные сценарии использования должны храниться отдельно в `description`, `useFor`, `avoidFor`, `aliases` и `status`.

## Статусы legacy / service

- `curwa` — `legacy`, скрыть из публичной витрины; canonical-смысл продолжен в `blogerka`.
- `breaking-bad` — `legacy/alias` для `heisenberg`; отдельный пользовательский стикер не нужен.
- `russian-passport`, `builder-master`, `spichka`, `haisenberg`, `medical-merbius` — `alias` старых имён; не показывать вторым экземпляром на витрине.
- `_favicon`, `og`, технические OG-иллюстрации — `service`, не показывать как пользовательские стикеры.
- растровые `magnify-1`, `magnify-2`, `passport-2`, `shibice`, `state-spies-1`, `state-spies-2` — legacy-варианты; не считать отдельными смыслами.

## Что переносить в движок

Канонический классификатор должен хранить минимум: `file`, локализованный `title`, буквальный `alt`, `description`, `tags/concepts`, `useFor`, `avoidFor`, `aliases`, `status`, `routes` и при необходимости `flip`. Витрина должна получать `title` и `alt` из этого классификатора, а не выводить смысл из filename. При подборе `ogSticker` для статьи агент должен сопоставлять классификатор с `CONTENT_INDEX.yml`, но явно заданный `ogSticker` остаётся приоритетным.
