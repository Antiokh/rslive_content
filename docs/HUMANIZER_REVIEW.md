# Humanizer RU review

Для русскоязычных MDX-изменений в pull request репозиторий запускает отдельный редакторский review на базе [`Antiokh/humanizer--ru`](https://github.com/Antiokh/humanizer--ru).

## Что запускается автоматически

GitHub Action берёт актуальную ветку `main` skill-репозитория и запускает его детерминированный `scripts/lint.py` по изменённым русскоязычным MDX-страницам.

Проверка сравнивает head-версию страницы с base-версией и выводит только новые срабатывания текущего PR. Старый редакционный долг не считается ошибкой автора текущего изменения.

Для каждого срабатывания комментарий показывает:

- `ERROR` или `WARN`;
- строку и правило humanizer;
- найденный фрагмент;
- рекомендацию по исправлению;
- суммарный severity `clean / review / rewrite`, а при наличии `ERROR` — `gate-fail`.

Комментарий один: при новом push он обновляется, а не создаётся заново.

## Что эта проверка не делает

- Не определяет авторство текста и не выдаёт «вероятность ИИ».
- Не запускает полный LLM-skill: семантический аудит, ручную фазу правки и слепую проверку нельзя воспроизвести обычным GitHub runner без отдельной модели/API.
- Не блокирует merge. Humanizer review остаётся advisory; технический `Content quality` отвечает за синтаксис и структуру контента.
- Не проверяет `/en/`, `/sr/` и файлы без достаточного количества русского текста.

## Безопасность fork-PR

Workflow использует `pull_request_target`, чтобы иметь право обновлять комментарий даже для PR из fork. При этом исполняемый review-скрипт всегда берётся из base-ветки репозитория. Head-ветка PR используется только как набор текстовых MDX-файлов: её scripts, workflows, зависимости и package-команды не запускаются.
