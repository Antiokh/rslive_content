# Матрица рекомендаций RelocationWizard

`RelocationWizard` — интерфейс движка RSLive, но список рекомендуемых статей и правила их подбора принадлежат контенту и редактируются вместе с энциклопедией.

## Источник истины

Канонический файл:

```text
src/content/docs/_data/relocation-wizard.json
```

Файл автоматически синхронизируется в `Antiokh/rslive.ru: astro/src/content/docs/_data/relocation-wizard.json` вместе с остальным `src/content/docs/**`. Не редактируйте синхронизированную копию в движке как основной источник.

Сам интерфейс, вопросы опросника, допустимые варианты ответов, фазы плана и код проверки находятся в `Antiokh/rslive.ru`. Поэтому обычный контентный PR может менять статьи, подписи карточек и условия показа в пределах уже существующей схемы ответов, но не должен придумывать новый вопрос или новое значение ответа.

## Формат

Корень файла имеет версию схемы и массив рекомендаций:

```json
{
  "schemaVersion": 1,
  "recommendations": []
}
```

Каждая рекомендация содержит:

- `id` — уникальный технический идентификатор правила;
- `progressId` — идентификатор прочтения материала. Несколько взаимоисключающих правил для одной статьи могут использовать один `progressId`, чтобы отметка «прочитано» была общей;
- `href` — существующий канонический внутренний маршрут вида `/arrival/boravak/`;
- `title` — заголовок карточки в навигаторе;
- `summary` — короткое объяснение, что находится в статье;
- `reason` — почему карточка показана при выбранных ответах;
- `phase` — место карточки в плане: `now`, `next`, `situation` или `later`;
- `match` — условия показа.

Пример:

```json
{
  "id": "pets-before-arrival",
  "progressId": "move-pets",
  "href": "/move/pets/",
  "title": "Переезд с питомцем",
  "summary": "Проверьте микрочип, вакцинацию, ветеринарные документы, требования перевозчика и правила границы.",
  "reason": "Вы указали, что едете с домашним животным.",
  "phase": "now",
  "match": {
    "stage": ["planning", "traveling"],
    "pets": ["yes"]
  }
}
```

## Как работает `match`

Разные поля внутри `match` соединяются по **И**. Значения внутри массива одного поля соединяются по **ИЛИ**.

Например:

```json
"match": {
  "stage": ["planning", "traveling"],
  "pets": ["yes"]
}
```

означает: показать карточку, если человек находится на этапе `planning` **или** `traveling`, **и одновременно** ответил `yes` на вопрос о питомце.

Текущая схема допускает такие поля и значения:

| Поле | Значения |
| --- | --- |
| `stage` | `planning`, `traveling`, `arrived`, `settled` |
| `stay` | `short`, `temporary`, `permanent`, `unsure` |
| `housing` | `searching`, `temporary`, `stable`, `buying` |
| `work` | `job_search`, `employee`, `freelance`, `business`, `student`, `not_working`, `unsure` |
| `family` | `adult`, `preschool`, `school`, `both` |
| `pets` | `no`, `yes` |
| `vehicle` | `no`, `license`, `foreign_car`, `buy` |

Если для новой логики не хватает вопроса или значения, сначала меняйте схему мастера в `Antiokh/rslive.ru`; не добавляйте неизвестное значение только в JSON.

## Редакционные правила

1. Ссылайтесь только на уже существующие страницы RSLive и используйте абсолютный канонический маршрут.
2. Подбирайте существующую статью, а не переносите юридическую или административную инструкцию в карточку мастера. `summary` и `reason` должны оставаться короткой навигационной подсказкой.
3. Не показывайте человеку заведомо пройденный или неприменимый этап, если текущих ответов достаточно, чтобы это определить.
4. Не создавайте две одновременно видимые карточки с одним `progressId`. Один `progressId` допустим у разных правил одной статьи, если условия этих правил взаимоисключающие.
5. При изменении административной, миграционной, налоговой или медицинской рекомендации сначала убедитесь, что сама целевая статья актуальна и подтверждена требуемыми источниками. Матрица не является отдельным источником юридических фактов.
6. Не добавляйте исполняемый JavaScript или выражения в `match`: это декларативные данные.

## Проверка изменений

После синхронизации движок проверяет матрицу командой `npm run test:relocation-wizard`: существование маршрутов, допустимые вопросы и значения, уникальность правил, обязательные продуктовые сценарии и отсутствие конфликтующих карточек в комбинациях ответов.

Для PR владельца репозитория workflow `Превью rslive.ru` копирует предложенный `src/content/docs/**` в актуальный движок и запускает обычную Cloudflare preview-сборку. После перехода мастера на контентную матрицу это является основной интеграционной проверкой контентных изменений правил.

Перед merge просмотрите preview и вручную проверьте как минимум изменённые комбинации ответов. Если изменился набор вопросов или допустимых значений, нужен связанный PR в `Antiokh/rslive.ru`.
