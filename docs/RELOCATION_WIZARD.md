# Frontmatter персонального навигатора

`RelocationWizard` подбирает существующие статьи RSLive по ответам пользователя. После миграции правила подбора принадлежат самим статьям и задаются опциональным полем `navigator` во frontmatter.

## Источник истины

Для конкретной статьи источник истины — её собственный frontmatter в `src/content/docs/**/index.mdx`.

Движок `Antiokh/rslive.ru` владеет вопросами, вариантами ответов, фазами и преобразованием ответов в navigator-теги. Контентный репозиторий владеет тем, какие статьи используют эти уже существующие теги.

`keywords` и `navigator` не взаимозаменяемы:

- `keywords` описывает поисковые формулировки и тему материала;
- `navigator` описывает условия показа статьи в персональном плане.

Отдельной recommendation-матрицы больше нет. Не дублируйте `navigator` в JSON, route-списках или других служебных файлах: классификация статьи должна оставаться рядом с самой статьёй.

## Синтаксис

Один набор условий записывается максимально коротко:

```yaml
navigator:
  now: [traveling, pets]
```

Внутри массива условия соединяются по **И**: пользователь должен одновременно быть `traveling` и иметь тег `pets`.

Несколько альтернатив одной фазы записываются как список массивов:

```yaml
navigator:
  now:
    - [traveling, pets]
    - [car, pets]
```

Между массивами действует **ИЛИ**. Таким образом, статья попадёт в `now`, если выполнен хотя бы один из двух AND-наборов.

Одна статья может участвовать в нескольких фазах:

```yaml
navigator:
  now: [before-arrival, pets]
  situation: [after-arrival, pets]
```

Заголовок карточки берётся из `title`, описание — из `description`, маршрут — из пути статьи. Отдельные `href`, `title`, `summary`, `reason` и `progressId` для навигатора не редактируются.

## Фазы

| Фаза | Смысл |
| --- | --- |
| `now` | ближайшие действия по текущей ситуации |
| `next` | следующий этап после ближайших действий |
| `situation` | материалы, актуальные именно для выбранной ситуации |
| `later` | то, что пригодится позже |

## Теги

Теги являются публичным редакторским словарём, но их семантика определяется движком. Не создавайте новый тег только в MDX.

| Тег | Когда активен |
| --- | --- |
| `planning` | пользователь только планирует переезд |
| `traveling` | пользователь уже едет или летит в Сербию |
| `arrived` | пользователь недавно приехал |
| `settled` | пользователь уже живёт в Сербии |
| `before-arrival` | `planning` или `traveling` |
| `after-arrival` | `arrived` или `settled` |
| `not-settled` | `planning`, `traveling` или `arrived` |
| `stay-short` | короткая поездка |
| `stay-temporary` | временное проживание на месяцы или годы |
| `stay-permanent` | долгосрочный сценарий |
| `stay-unsure` | пользователь пока не определился со сроком |
| `long-stay` | `stay-temporary`, `stay-permanent` или `stay-unsure` |
| `housing-searching` | ищет аренду |
| `housing-temporary` | жильё временное |
| `housing-stable` | жильё уже устроено |
| `housing-buying` | планирует покупать недвижимость |
| `job-search` | ищет работу |
| `employee` | работает по найму |
| `freelance` | удалённая работа или фриланс |
| `business` | предпринимательский сценарий |
| `student` | учёба или поступление |
| `not-working` | сейчас не работает и не учится |
| `work-unsure` | ещё не выбрал рабочий сценарий |
| `adults-only` | в семейном сценарии только взрослые |
| `preschool-age` | есть ребёнок дошкольного возраста; также активен для варианта «дети разных возрастов» |
| `school-age` | есть ребёнок школьного возраста; также активен для варианта «дети разных возрастов» |
| `pets` | едет или живёт с питомцем |
| `no-pets` | питомца нет |
| `no-car` | автомобильный блок не нужен |
| `foreign-license` | есть иностранные права: вариант «только права» или собственный иностранный автомобиль |
| `foreign-car` | едет или живёт со своим автомобилем на иностранных номерах |
| `buy-car` | планирует купить автомобиль в Сербии |
| `car` | `foreign-car` или `buy-car` |
| `driving` | любой сценарий, где пользователь планирует водить: иностранные права, иностранный автомобиль или покупка автомобиля |

## Редакционные правила

1. Добавляйте `navigator` только если статья действительно полезна для указанной ситуации.
2. Используйте самый общий существующий тег, который точно выражает условие. Например, вместо двух альтернатив `[planning]` и `[traveling]` обычно предпочтителен `[before-arrival]`.
3. Не добавляйте теги «на всякий случай»: слишком общая карточка засоряет персональный план.
4. Если одной фазы достаточно одного AND-набора, используйте короткую форму массива. Вложенные массивы нужны только для реального **ИЛИ**.
5. Не дублируйте в navigator заголовок, описание или URL статьи.
6. Статья с `navigator` должна иметь непустой `description`, потому что он используется как текст карточки.
7. Если нужного тега нет, сначала измените schema/tag mapping в `Antiokh/rslive.ru`, обновите эту документацию и линтер; только после этого используйте тег в статье.

## Проверка

`tools/content-quality/lint-content.mjs` проверяет navigator на всём корпусе:

- объект должен содержать только поддерживаемые фазы;
- значение фазы должно быть либо одним непустым массивом тегов, либо непустым списком таких массивов;
- неизвестные и повторяющиеся теги запрещены;
- одинаковые OR-ветки запрещены;
- у статьи должен быть `description`;
- локализованные `/en/` и `/sr/` страницы пока не должны подключаться к русскоязычному мастеру.

Движок дополнительно проверяет frontmatter через Astro schema. При Astro build он собирает фактический список рекомендаций только из `navigator` и перебирает все 14 336 комбинаций ответов: персональный план не должен быть пустым и одна статья не должна одновременно появляться в нескольких фазах.
